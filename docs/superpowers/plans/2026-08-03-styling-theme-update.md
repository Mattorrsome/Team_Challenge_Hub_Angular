**Goal:** Apply the brand palette, add a working dark mode, make every view
mobile-friendly, stop button labels wrapping, and right-align the list
toolbar with a capped desktop width.

**Architecture:** Dark mode rides on Angular Material's native
`theme-type: color-scheme`, which emits every `--mat-sys-*` token as a CSS
`light-dark()` pair. The toggle then only has to set the `color-scheme`
property on `<html>` — all Material components flip with no per-component
dark styling. Brand colors enter as M3 tonal palettes generated from the
brand hex seeds, with the two key surfaces overridden to the exact brand hex.
App-authored CSS uses `light-dark()` for its own colors, matching the same
mechanism.

**Tech Stack:** Angular 22.0.8, Angular Material 22.0.8 (M3 theming, SCSS),
Vitest for unit tests.

## Verified Framework Facts

These were checked against the installed `@angular/material@22.0.8` before
this plan was written — treat them as given, do not re-derive:

- `mat.theme()`'s `color.theme-type` accepts `light` (the current default),
  `dark`, or `color-scheme`
  (`core/theming/_config-validation.scss:102-106`).
- With `theme-type: color-scheme`, every system color is emitted as
  `light-dark($lightValue, $darkValue)`
  (`core/tokens/_system.scss:248-256`), so native CSS resolves it from the
  `color-scheme` property.
- `mat.theme-overrides((name: value, ...))` emits system-level CSS variable
  overrides (`core/tokens/_system.scss:190`). Use it for the exact-hex
  surfaces.
- `mat.theme()`'s `primary`/`tertiary` must be **M3 palette maps, not raw hex**
  — `_definition.scss:41-54` does `map.get($primary, secondary)` and
  `map.remove($primary, neutral, ...)` on them, and `validate-palette`
  rejects anything else. This is why the palette must be generated by the
  schematic rather than passing `#007FBA` directly.
- Sass emits an unknown `light-dark(...)` call through to CSS verbatim —
  Material's own token code relies on this.

```scss
// Angular Material M3 theming. Brand palettes are generated from the brand hex
// seeds by `ng generate @angular/material:theme-color` — see
// .claude/skills/team-challenge-colors/SKILL.md for the palette and its rules.
@use '@angular/material' as mat;
@use './app/styles/theme-colors' as brand;

html {
  height: 100%;

  // theme-type: color-scheme emits every system color as a CSS light-dark()
  // pair, so flipping the `color-scheme` property on this element switches the
  // whole app — including every Material component — with no per-component
  // dark styling.
  @include mat.theme(
    (
      color: (
        primary: brand.$primary-palette,
        tertiary: brand.$tertiary-palette,
        theme-type: color-scheme,
      ),
      typography: Roboto,
      density: 0,
    )
  );

  // M3 derives its surfaces from the neutral ramp, which lands near but not
  // exactly on the brand values. Pin the two the brand specifies exactly.
  @include mat.theme-overrides(
    (
      surface: light-dark(#ffffff, #070c14),
      on-surface: light-dark(#070c14, #ffffff),
    )
  );

  // The ThemeService overwrites this at runtime from the persisted choice, and
  // the inline script in index.html sets it before first paint. Light is the
  // default for a first-time visitor.
  color-scheme: light;
}

body {
  background-color: var(--mat-sys-surface);
  color: var(--mat-sys-on-surface);
  font: var(--mat-sys-body-medium);

  // Reset the user agent margin.
  margin: 0;
  height: 100%;
}
```

Note `color-scheme` moved from `body` to `html`: `light-dark()` resolves
against the element's own computed `color-scheme`, and the Material tokens
are emitted on `html`, so the property has to live there.

```markdown
## Theming mechanism

Light/dark runs on Angular Material's `theme-type: color-scheme` (configured
in `src/styles.scss`), which emits every `--mat-sys-*` color as a CSS
`light-dark(light, dark)` pair. Switching themes only sets the `color-scheme`
property on `<html>` — see `src/app/core/theme/theme.service.ts`.

## Rules for new styling

- **Never hardcode a hex value in component SCSS.** Use a Material system
  token: `var(--mat-sys-on-surface)`, `var(--mat-sys-on-surface-variant)`
  (secondary text), `var(--mat-sys-outline-variant)` (borders),
  `var(--mat-sys-primary)` (interactive), `var(--mat-sys-error)` (errors).
- If no token fits, write `light-dark(<light>, <dark>)` — never a bare hex,
  which would be wrong in one of the two themes.
- **Do not** add `:root`/`[data-theme]` custom properties for colors. Such
  properties cannot restyle Angular Material components, which read
  `--mat-sys-*`; a second system would silently diverge.
- Do not emit `color-scheme: light dark` — this app follows the user's
  explicit choice, not the OS setting.
```

- [ ] **Step 3: Write `ThemeService`**

Create `src/app/core/theme/theme.service.ts`:

```typescript
import { Injectable, signal } from '@angular/core';

export type Theme = 'light' | 'dark';

const STORAGE_KEY = 'tch_theme';

@Injectable({ providedIn: 'root' })
export class ThemeService {
  private readonly current = signal<Theme>(this.readStoredTheme());

  readonly theme = this.current.asReadonly();

  constructor() {
    // The inline script in index.html already applied the stored theme before
    // first paint; re-applying here keeps the DOM correct when the service is
    // constructed in a context that script never ran in (unit tests, SSR).
    this.apply(this.current());
  }

  toggle(): void {
    const next: Theme = this.current() === 'dark' ? 'light' : 'dark';
    this.current.set(next);
    localStorage.setItem(STORAGE_KEY, next);
    this.apply(next);
  }

  private apply(theme: Theme): void {
    // Setting `color-scheme` is the whole switch: every Material system color
    // is emitted as light-dark(), which CSS resolves from this property.
    // Deliberately never 'light dark' — the app follows the user's explicit
    // choice, not the OS setting.
    document.documentElement.style.colorScheme = theme;
  }

  private readStoredTheme(): Theme {
    return localStorage.getItem(STORAGE_KEY) === 'dark' ? 'dark' : 'light';
  }
}
```
